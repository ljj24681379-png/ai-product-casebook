# AI 反馈洞察 Agent：从非结构化反馈到迭代决策

## 用户问题

用户反馈数量大、表达非结构化，评价原因经常缺失。只看单条反馈很难还原真实诉求和回答问题，人工逐条关联会话、分类和整理也无法持续运行。

## 产品判断

反馈分析应被产品化为可重复运行的 Agent 工作流：让模型理解意图和对话语义，让程序处理数据关联与确定性检查，再由人工复核关键判断。

## 关键方案

- 设计“数据获取—会话还原—需求识别—问题分类—原因分析—优先级判断—报告输出”链路；
- 使用 Python、SQL 与大模型调用组织处理流程；
- 通过任务拆解、上下文组织、分类规则和结构化输出提高一致性；
- 按模型、Prompt／Skill、工具和数据来源组织问题归因；
- 输出可追溯案例与 P0—P2 治理清单，支持需求排序和版本验收。

## 结果

- 建立按周运行的反馈分析机制；
- 累计处理约 12 万条用户反馈；
- 沉淀约 5 万条高质量数据和结构化案例库；
- 结合 6 轮、3,200 条高考专项评测与办公文件检查，支持模型比较和版本验收。

## 复盘

大模型适合理解复杂语义，程序适合关联、计算和校验，人工负责高风险判断。把三者放进稳定流程，比让模型一次生成总结更可靠。
